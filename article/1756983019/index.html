高频操作系统面试题

下面按面试高频度整理一版操作系统题。你可以把它当成“背诵骨架 + 面试表达稿”。重点不是死记概念，而是能讲清楚：是什么、为什么、怎么用、出问题怎么排查。

一、进程和线程有什么区别？

进程是资源分配的基本单位，线程是 CPU 调度的基本单位。

进程有独立的地址空间、文件描述符、堆、全局变量等资源；线程共享进程的地址空间和大部分资源，但每个线程有自己的栈、寄存器、程序计数器。

面试回答：

进程之间隔离性强，一个进程崩溃一般不会影响其他进程，但进程切换成本较高。线程更轻量，共享内存，通信方便，但也带来并发安全问题，比如共享变量竞争、死锁等。

二、进程间通信方式有哪些？

常见 IPC 方式：

区别：

  • 管道适合有亲缘关系的进程。
  • 命名管道可以用于无亲缘关系进程。
  • 消息队列适合结构化消息传递。
  • 共享内存最快，但需要信号量/锁保证同步。
  • Socket 可用于跨机器通信。
  • 信号适合事件通知，不适合传大量数据。

面试重点：

共享内存性能最高，因为避免了多次内核态和用户态的数据拷贝，但它只解决数据共享，不解决并发控制，所以通常需要配合信号量或互斥锁。

四、什么是用户态和内核态？为什么要区分？

用户态是普通应用程序运行的状态，权限受限；内核态是操作系统内核运行的状态，权限高，可以访问硬件、内存管理、进程调度等核心资源。

为什么区分：

  • 防止应用程序随意操作硬件。
  • 防止应用程序破坏内核或其他进程。
  • 提高系统安全性和稳定性。

例如应用程序调用 read()、write()、fork()，最终都要进入内核态执行。

五、系统调用是什么？

系统调用是用户程序访问操作系统内核能力的接口。

比如：

应用程序不能直接操作磁盘、网卡、进程调度等资源，只能通过系统调用请求内核完成。

面试表达：

系统调用本质上是一种受控的用户态到内核态切换，代价比普通函数调用高，因为涉及权限级别切换、上下文保存和恢复。

六、什么是上下文切换？为什么开销大？

上下文切换是 CPU 从一个任务切换到另一个任务时，保存当前任务状态并恢复另一个任务状态的过程。

需要保存和恢复：

为什么开销大：

  • CPU 寄存器状态要保存和恢复。
  • 可能导致 CPU cache 失效。
  • 进程切换还可能涉及页表切换。
  • 频繁切换会降低吞吐量。

面试补一句：

线程切换一般比进程切换轻，因为同一进程内的线程共享地址空间，不需要切换完整的内存映射。

七、并发和并行有什么区别？

并发是多个任务在同一时间段内交替执行，看起来同时进行。

并行是多个任务在同一时刻真正同时执行，需要多核 CPU 支持。

八、死锁是什么？产生条件是什么？

死锁是多个线程或进程互相等待对方持有的资源，导致所有参与者都无法继续执行。

死锁四个必要条件：

解决方式：

  • 破坏占有且等待：一次性申请所有资源。
  • 破坏不可抢占：允许资源被强制释放。
  • 破坏循环等待：按固定顺序申请资源。
  • 超时机制：拿不到锁就回滚或重试。
  • 死锁检测：发现环路后终止部分任务。

面试回答：

工程中最常用的是固定加锁顺序、锁超时、减少锁粒度，以及避免在持锁期间做耗时 IO。

九、互斥锁、自旋锁、读写锁区别？

互斥锁：

  • 拿不到锁会阻塞线程。
  • 适合临界区执行时间较长的场景。

自旋锁：

  • 拿不到锁不会阻塞，而是一直循环等待。
  • 避免线程睡眠和唤醒开销。
  • 适合锁持有时间极短的场景。
  • 单核 CPU 上不适合自旋锁。

读写锁：

  • 多个读线程可以并发。
  • 写线程互斥。
  • 适合读多写少场景。

面试表达：

如果临界区很短，自旋锁可能更划算；如果临界区较长，用互斥锁更合适，否则自旋会浪费 CPU。

十、什么是虚拟内存？

虚拟内存是操作系统给每个进程提供的独立、连续的地址空间。

好处：

  • 每个进程认为自己独占内存。
  • 进程之间地址空间隔离。
  • 可以使用比物理内存更大的地址空间。
  • 支持按需加载和换页。
  • 简化程序内存管理。

虚拟地址需要通过页表映射到物理地址。

十一、分页和分段有什么区别？

分页：

  • 按固定大小切分内存，比如 4KB 一页。
  • 主要解决内存管理和碎片问题。
  • 会产生内部碎片。

分段：

  • 按逻辑模块切分，比如代码段、数据段、堆、栈。
  • 更符合程序逻辑。
  • 会产生外部碎片。

现代系统通常以分页为主，也可能结合分段机制。

十五、select、poll、epoll 区别？

select：

  • 使用固定大小 bitmap。
  • 连接数有限制。
  • 每次调用都要把 fd 集合从用户态拷贝到内核态。
  • 需要遍历所有 fd。

poll：

  • 使用链表结构，没有固定 fd 数量限制。
  • 仍然需要遍历所有 fd。
  • 性能随 fd 数量增加而下降。

epoll：

  • 事件驱动。
  • 内核维护 fd 集合。
  • 只返回就绪事件。
  • 适合高并发连接场景。

面试表达：

select 和 poll 的问题在于每次都要重复传递和扫描大量 fd，而 epoll 把 fd 注册到内核，只在事件就绪时通知应用，所以更适合大量连接但活跃连接较少的场景。

十六、epoll 的 LT 和 ET 模式区别？

LT：水平触发。

只要 fd 还有数据没读完，epoll 就会不断通知。

ET：边缘触发。

只有状态发生变化时通知一次，比如从无数据变成有数据。

区别：

  • LT 编程简单，不容易漏事件。
  • ET 性能更高，但必须一次性把数据读到 EAGAIN。
  • ET 通常配合非阻塞 IO 使用。

面试表达：

ET 模式如果没有把数据读完，后续可能不会再收到通知，导致连接卡住，所以必须使用非阻塞 IO 并循环读到 EAGAIN。

十九、软链接和硬链接区别？

硬链接：

  • 多个文件名指向同一个 inode。
  • 删除原文件，硬链接仍然可用。
  • 不能跨文件系统。
  • 一般不能链接目录。

软链接：

  • 类似快捷方式，保存目标路径。
  • 可以跨文件系统。
  • 可以链接目录。
  • 原文件删除后，软链接失效。

二十、孤儿进程和僵尸进程区别？

孤儿进程：

  • 父进程退出，子进程还在运行。
  • 会被 init 或 systemd 接管。
  • 一般不是问题。

僵尸进程：

  • 子进程已经退出。
  • 父进程没有调用 wait() 回收子进程状态。
  • 进程表中还残留记录。
  • 大量僵尸进程会耗尽 PID 资源。

解决方式：

  • 父进程正确调用 wait/waitpid。
  • 处理 SIGCHLD 信号。
  • 修复父进程逻辑。

二十一、内核态线程和用户态线程区别？

用户态线程：

  • 由用户态线程库管理。
  • 创建和切换快。
  • 内核感知不到。
  • 一个线程阻塞可能导致整个进程阻塞。

内核态线程：

  • 由内核管理和调度。
  • 可以利用多核。
  • 阻塞一个线程不会影响其他线程。
  • 创建和切换成本更高。

现代主流线程模型通常是 1:1，即一个用户线程对应一个内核线程。

False Sharing 指多个线程修改不同变量，但这些变量刚好在同一个 cache line 上，导致 cache line 在多个 CPU 核之间频繁失效。

它不是传统意义上的零拷贝，但也用于减少不必要缓存和拷贝。

适合：

  • 数据库
  • 自己管理缓存的系统

十三、零拷贝不是“完全没有拷贝”

这是面试很重要的纠偏点。

更准确的理解：

数据从磁盘到内存、从内存到网卡，这些 DMA 拷贝仍然存在。

所以可以这样表达：

零拷贝并不是物理意义上没有任何数据移动，而是避免数据在内核态和用户态之间来回复制，减少 CPU 拷贝和上下文切换。真正的数据传输仍然需要 DMA 完成。

十四、面试版完整回答

可以直接这样讲：

零拷贝主要用于优化文件到网络这类 IO 场景。传统 read + write 会经历磁盘到 Page Cache、Page Cache 到用户 buffer、用户 buffer 到 Socket Buffer、Socket Buffer 到网卡这四次拷贝，并且有四次用户态和内核态切换。这里真正浪费的是两次 CPU 拷贝，因为应用只是转发数据，并不需要读取和修改内容。

零拷贝通过 sendfile、mmap 等机制，让数据尽量在内核态完成流转。比如 sendfile 可以把文件数据从 Page Cache 直接发送到 Socket，避免进入用户态，减少上下文切换和 CPU 拷贝。如果网卡支持 Scatter-Gather DMA，Socket Buffer 甚至只需要保存 Page Cache 中数据的描述符，由 DMA 直接从 Page Cache 发送到网卡。

所以零拷贝不是完全没有拷贝，而是减少 CPU 参与的冗余拷贝。它非常适合 Kafka、Nginx、文件服务器这类文件内容不需要应用层加工、直接发送到网络的场景。但如果数据需要压缩、加密、修改或业务解析，就仍然需要进入用户态处理，零拷贝收益会下降。

这版回答基本可以覆盖大多数面试追问。
